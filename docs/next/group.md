# 群组协同：报告（2026-11-15 / 16）

kumo 与 Claude 的设计讨论整理。前半是 `channels` 分支上已经做完的，后半是多份上下文与记忆的结论。

## 方向

从“多会话协同”转为“群组内协同”：一个会话就是一个群，agent 之间、agent 与人之间都在群里往来；侧栏平铺，只列人开的会话和群；谁在干活、谁在问，都在群里看到。面向互相信任的团体和个人，成员之间不设权限（kumo，2026-11-16）。

## 已完成（`channels` 分支，测试实例在跑）

**拉起与成员**
- 会话里 `ir new` 开的 agent 直接作为成员进入拉起者正在为之干活的群（否则拉起者自己的群），`recv` 为 `at`；`launcher` 只记谁开的，归档时一起归档。
- 一个群至多 8 个邀请的 agent，拉起的不占这 8 个，合计至多 32。
- 为群开的会话、子代理、workflow 都不进侧栏，从群顶栏的成员键进去（子代理在“在干活的子代理”一节，只读）；跳转框都能搜到。

**提问与报错**
- 群里每个 agent 的提问、审批、计划进它所在的每个群，输入框上方排成一队，最早的展开，其余“还有 N 个”；群里的人和 bot 都能答，先答的算。
- agent 被叫起却因出错没说话，群里写明原因（余额不足、认证失败、请求太频繁，否则错误首行）；它的报错进它所在的每个群。

**会话页**
- 会话页不再换页：始终是一个页面，群里别人说的话按时间并入本会话 agent 的记录；只有一个 agent 时与以前完全一样。
- 打开会话一次请求取齐第一屏（`GET /v1/internal/sessions/{id}/first`），整屏一次画出，刷新不跳。
- 交接：被叫的 agent 的头像框等叫它的那句话完整出现再进来（至多 1.5 秒），先撑开高度再浮上来；子代理在发起它的那步工具调用下面有头像框。
- agent 之间的话超过 6 行折起（“还有 N 行”），给人的话不折。
- 已读头像加大，已读里不出现 Iridium；主机一律写作 Iridium，用 Iridium 的标。

**其他**
- 邀请菜单：模型直接弹出（服务端先回存下的，页面打开成员菜单时预取并存在浏览器），dsh 有预设；点一行就用默认模型加入，默认模型标“默认”，没有实心按钮。
- agent 在群里发话只用 `content='…'`（单引号里可多行），去掉了 `k=@-`；手动审批下这一种写法免审批。
- 交给 agent 的来源标签：本机的人也是 Iridium，Iridium 自己的话按终端区分。

## 多份上下文与记忆：不新造（kumo，2026-11-16）

只用 agent 自带的功能和本分支已有的部分；记忆只来自真实的记录，不由模型改写。

| 想要的 | 做法 |
|---|---|
| 同一个 agent 出现在几个群 | 邀请已有的会话进别的群：同一份上下文 |
| 上下文满了 | agent 自己的自动压缩；`/compact` 照常转给它 |
| 换一份干净的上下文 | `/clear`：新会话接替，称呼、头像、所在的群跟过去 |
| 新上下文要知道以前的事 | agent 用 `ir` 读旧会话的提要和原文；人用 `&` 提及那个会话 |
| 长期记住的东西 | Claude 自带的 memory，各 agent 的 `CLAUDE.md` / `AGENTS.md`，不限制写什么 |
| 同一个群里并行 | 再邀请一个 agent |

代价：一份会话进多个群，各群内容进同一个窗口，压缩更频繁；它一次只跑一个回合，两个群同时叫它要排队；`/clear` 之后是真的忘了，除非去读旧记录或写进过 memory。

模型压缩上下文后，已读不变、不会重新读，需要时用 `message.list`（可按词搜）找回原话。

### 讨论过、否决的

- 话题（`#名字`，群下的讨论串）：群一级的结构，动到编号、已读、提问队列、Satori 和应用，影响面太大。
- 身份表加“新上下文 / 切换”：要人操作，麻烦。
- 用模型的“里”（后台会话整理记忆条目，仿 Letta 的 Claude Subconscious）：多一套会话、触发规则和说明；记忆由模型写，可能写错。
- 续接（新会话带一张按记录拼出的交接单）：过度设计。

## 待做：资料卡、介绍、模糊记忆（kumo，2026-11-16 定）

已在 `channels` 分支做完（2026-11-16），以 `docs/channels.md` 的“资料”“角色”“记忆”“agent 知道的自己”“有人 @ 我”为准。和下面的设计不同的地方：`GET internal/me` 已被占用，自己的卡是 `internal/self`；查记录是 `internal/recall`；这一段随系统提示给（进程每次启动），不随消息；另加了角色和 agent 主动写的记忆。

agent 是一个“人”：资料卡上有背景和介绍；对别的群、对清空以前的事只有模糊的印象，印象都取自记录，想弄清楚就用 `ir` 查。和 `channels` 分支一起做完再发版。

### 资料卡

- 上面一条背景图，头像压在背景下沿，下面是称呼、模型和状态、介绍，最后是按钮。人、AI、应用同一张卡。
- 背景和头像存在一起，上传后缩到固定宽度；没设时是一块平的底色。
- 介绍：一段文字，至多 200 字。人的是个性签名，在自己的资料页改；AI 的跟着会话（同称呼，`/clear` 后转给接替的会话）；应用的跟着应用。
- 四个字段（称呼、介绍、头像、背景）人、agent、群都有；群的称呼是群名。谁能改见“改资料”。

### 介绍就是人设

AI 的介绍同时写进给它的固定说明里“你是谁”那一段。Claude 仍原样运行，随消息注入。

### 模糊记忆

随固定说明一起给（第一次被叫起、说明变了、压缩之后、`/clear` 之后），约 200–400 token，只放从记录里直接取的事实：

- 它是谁：称呼、介绍。
- 它在哪些群（最近的 8 个）：上次发话的时间、和谁、它最后一句的开头。
- 它之前的上下文（最近 3 份）：何时清空、多少回合、第一句的开头。要补：`/clear` 时记下上一份是哪个会话。
- 群里的人和各自的签名。
- 一行指路：`ir api recall q='词'`。

### `ir` 工具

| 命令 | 作用 |
|---|---|
| `ir api GET internal/me` | 自己的卡：称呼、介绍、模型、所在的群和各自的最近动态、之前的上下文 |
| `ir api recall q='词'` | 搜遍它所在各群的消息、自己的记录、清空前的记录；每条写明在哪、何时、谁、开头几个字和取全文的写法。加参数可搜它看得见的全部 |
| `ir api GET internal/members/<称呼或用户>` | 查一个人或 agent：介绍、同在哪些群、最近说的话 |

三条都只读，手动审批下免审批。细看仍用 `block.outline`、`block.list`、`message.get`。

### 改资料

| 命令 | 改谁 |
|---|---|
| `ir api PATCH internal/me nick=… intro='…' avatar=… background=…` | 自己 |
| `ir api PATCH internal/members/<称呼> …` | 群里别的 agent，包括它拉起的 |
| `ir api PATCH internal/channels/here name=… intro='…' avatar=… background=…` | 当前的群 |

- `avatar`、`background` 可以是图片路径，也可以是一个表情（放在平的底色上）或一个颜色（`#2f4f6f`）。
- 群里任何成员（人、agent）都能改任何 agent 和群的资料；人的资料只有本人能改。
- 拉起时带上：`ir new agent=codex nick=tester intro='只跑测试，不改代码' avatar=🧪 text='…'`；不给就是默认称呼，之后再改。页面上邀请时不加输入项，进来后在资料卡里改。
- 页面：头像菜单的“改名”“换头像”合成“编辑资料”，打开一个子页面（称呼、介绍、头像、背景）；成员列表的入口打开同一个。

### 教 agent 改资料

- 固定说明里一行（约 40 token，只在第一次被叫起、压缩后、清空后给）：资料可以改，写法见 `ir api help profile`；职责明确了、职责变了、有人要求时改，和手头的事放在同一回合里做，别的时候不改。
- `ir new` 没带资料时，回执里附一句可在拉起时给 `nick`、`intro`、`avatar`。
- 取值和例子在 `ir api help profile`。
- 同一回合里 agent 改了多次，群里只记一行。

### 资料变了怎么告诉 agent

- 不叫起谁。跟着它下一次被叫起的那条消息给一节 `<profile-changes>`，一行一处：谁把什么由什么改为什么（它自己的、群的、别的成员的）。
- 按快照比：每个 agent 在每个群记着上次告诉它的资料，叫起时和现在的比，不同的字段才写；中间改了多次只写最终值，没变就没有这一节。
- 图片只写“头像已换”“背景已换”。agent 自己改的不回告诉它。
- 群改名、换称呼、改介绍不再让固定说明重给全文（现在按全文哈希比）：只走这一节。
- 对人：群里记一行灰字，不计未读、不推送。

### 清空

agent 头像的右键（长按）菜单加“清空”，排在“压缩”后面：就是 `/clear`，对订阅来的 agent 也能用；点了先出确认卡（同“移出”那张的做法）。

### 有人 @ 我

现在 @ 一个人只是画成链接，没有别的。加上：

- 什么算：`@我的名字`、`@全体成员`、有人引用了我的话；agent @ 人和人 @ 人一样。
- 侧栏：那个群的第二行前面红字“[有人@我]”（只是 `@全体成员` 时写“[@全体成员]”），后面照旧“谁: 最后一句”；读到那条后消失。
- 角标：免打扰的群里，@ 我的那条也按红底计数。
- 服务端按登录记这个群里第一条没读的 @ 我的消息编号，已读位置过了就清；换设备也在。
- 推送：被 @ 时推一条，免打扰的群也推。
- 应用不用改：Satori 的消息里本来就带 `<at id>`。

### 不出现“默认”（kumo，2026-11-16）

页面上任何选模型、显示模型的地方都不写“默认”，写的是实际的模型名。

- 模型列表：agent 报来的 `default` 那一项不单独成行，并进它实际指向的那个模型的行；没选过模型时，勾着的就是那一行。指向的模型不在列表里，就按它的真名加一行。
- 显示：一律用正在用的模型（`SessionState.model`），不用选的值（`pick`）；现在取不到名字时写“默认模型”的地方（`web/src/chat/meters.tsx`）改掉。
- 还没开过的会话（新会话页、邀请菜单）：用服务端存下的那份模型表里它指向的模型；agent 没说哪个是默认的（dsh），用这台机器上这种 agent 上次实际跑的模型；都没有时只写 agent 的名字，握手后补上。
- 邀请菜单：行尾的“默认”去掉；agent 那一行直接写点它会用的模型（`Claude · Opus 5.5`），子菜单里那个模型排第一。
- 思考强度同理：没设过时显示 agent 实际在用的那一档（`effortNow`），不写“默认”。
- 接口照旧收 `""` 和 `default`（agent 自己的），回给页面和 `ir` 的是模型名。
- 推送规则里的“跟随默认”是另一回事，不在此列。

## 参考（否决的方案所依据的）

- Slack 里的 AI 助手：同一个机器人，一个讨论串一份上下文（[Slack: Agents & Assistants](https://api.slack.com/docs/apps/ai)）。
- Linear 的 agent 接口：agent 是一个用户，每次被派活开一个 AgentSession，有自己的状态（[Linear: Agent Interaction](https://linear.app/developers/agent-interaction)）。
- Letta：同一记忆块挂到多个 agent，一处改处处见（[Letta: Shared memory blocks](https://docs.letta.com/guides/agents/shared-memory-blocks)）。

## 遗留

- 拉起的会话有人直接说过话后是否进侧栏：先不管。
- 顶栏成员键是单独加载的，可能比对话晚一点出现；无 agent 的群页面没改；第二次回到看过的多 agent 会话仍会再取一次状态和成员。
- `internal/session` 的 `TestQueue` 满负载下偶发失败，原因未查。
- 把会话移出文件夹（侧栏顶上一组不属于任何文件夹的）：讨论过，先不加（kumo，2026-11-16）。Discord 的频道也不能移出服务器。
