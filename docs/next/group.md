# 群组协同：报告（2026-11-15 / 16）

kumo 与 Claude 的设计讨论整理。前半是 `channels` 分支上已经做完的，后半是定了方向、还没动手的“身份、会话、话题、记忆”。

## 方向

从“多会话协同”转为“群组内协同”：一个会话就是一个群，agent 之间、agent 与人之间都在群里往来；侧栏平铺，只列人开的会话和群；谁在干活、谁在问，都在群里看到。面向互相信任的团体和个人，成员之间不设权限（kumo，2026-11-16）。

## 已完成（`channels` 分支，测试实例在跑）

**拉起与成员**
- 会话里 `ir new` 开的 agent 直接作为成员进入拉起者正在为之干活的群（否则拉起者自己的群），`recv` 为 `at`；`launcher` 只记谁开的，归档时一起归档。
- 一个群至多 8 个邀请的 agent，拉起的不占这 8 个，合计至多 32。
- 为群开的会话、子代理、workflow 都不进侧栏，从群顶栏的成员键进去（子代理在“在干活的子代理”一节，只读）；跳转框都能搜到。

**提问与报错**
- 群里每个 agent 的提问、审批、计划进它所在的每个群，输入框上方排成一队，最早的展开，其余“还有 N 个”；群里的人和 bot 都能答，先答的算。
- agent 被叫起却因出错没说话，群里写明原因（余额不足、认证失败、请求太频繁，否则错误首行）；它的报错进它所在的每个群。

**会话页**
- 会话页不再换页：始终是一个页面，群里别人说的话按时间并入本会话 agent 的记录；只有一个 agent 时与以前完全一样。
- 打开会话一次请求取齐第一屏（`GET /v1/internal/sessions/{id}/first`），整屏一次画出，刷新不跳。
- 交接：被叫的 agent 的头像框等叫它的那句话完整出现再进来（至多 1.5 秒），先撑开高度再浮上来；子代理在发起它的那步工具调用下面有头像框。
- agent 之间的话超过 6 行折起（“还有 N 行”），给人的话不折。
- 已读头像加大，已读里不出现 Iridium；主机一律写作 Iridium，用 Iridium 的标。

**其他**
- 邀请菜单：模型直接弹出（服务端先回存下的，页面打开成员菜单时预取并存在浏览器），dsh 有预设；点一行就用默认模型加入，默认模型标“默认”，没有实心按钮。
- agent 在群里发话只用 `content='…'`（单引号里可多行），去掉了 `k=@-`；手动审批下这一种写法免审批。
- 交给 agent 的来源标签：本机的人也是 Iridium，Iridium 自己的话按终端区分。

## 待做：身份、会话、话题、记忆

### 名词

| 名词 | 代码 | 是什么 |
|---|---|---|
| 身份 | `persona` | 被 @ 的那个“人”：称呼、头像、agent 类型、模型。群里显示为一个成员 |
| 会话 | `session` | 身份的一份上下文（不变：会话是托管 agent 的私有上下文） |
| 话题 | `thread` | 群里的一条讨论串；同一身份在一个群里有几份上下文，就是有几个话题 |
| 记忆 | `memory` | 叫起时注入的一节，分索引、提要、原文三层 |

### 身份

- 称呼、头像从会话移到身份上。现有的每个会话各算一个身份，不自动合并；页面上可以把两个合成一个。
- 邀请已有身份进别的群，或在话题里叫它，就给它开一份新会话，沿用称呼和头像。
- 成员资料卡列出这个身份的全部会话。四种 agent 都支持。
- 全部开放：同一身份的所有会话（含私聊）互相可见，不设共享开关。

### 话题（`#`）

- `#名字` 是话题，`#数字` 仍是消息编号；话题名不能是纯数字，中文、字母、数字、`_`、`-`，至多 24 字，群内不重名。
- 输入框打 `#` 弹出话题列表（最近活跃在前），最后一项“新话题：…”。`#登录页 @claude 接着改`：发进该话题，叫起 claude 在该话题里的会话；话题不存在就新建。打开某个话题后发话不用写 `#`。
- 一个话题里，每个被叫过的身份各有一份会话，第一次被叫时才开。不带 `#` 是群的主线，每个身份在主线上有自己的主会话。
- 主线里一个话题只占一行（`# 登录页 · claude8、codex · 12 条 · 最新一句`，带未读），点开在侧边或原地展开；正文里的 `#登录页` 是可点的链接；agent 在话题里被叫起，回复回到该话题。
- 话题可以结束：其中的会话一起归档，可恢复。
- 已读、未读、提问队列按话题分开算，主线那一行汇总。
- Satori：话题是群下的子频道（`parent_id` 为群），应用照常收发。

### 记忆（渐进式）

- **索引**（自动注入）：同一身份的其他每个会话一行：在哪个群、哪个话题，自上次看后几轮，最新一句要点，附展开命令。没有新东西的不出现，全都没有就不注入。每行约 30–50 token。
- **提要**（agent 自己展开）：现有 `block.outline`，每轮谁让干什么、做了什么、最后说了什么。
- **原文**（再展开）：现有 `block.list`。
- 两个位置：告知位置（上次在索引里说到哪，判断有无新东西）、查看位置（上次自己展开到哪，索引里“自你上次看后”和展开的 `from` 从这里算）。
- 自动附上提要只在：这次的消息点名了那个会话（话题名、群名），或那份新内容不足约 150 token。
- 展开命令只读，手动审批下免审批。
- 不调用模型做摘要，由 Iridium 按记录生成；agent 只读不写（避开 Letta 提醒的多 agent 同改一块丢内容）。
- 注入的记忆不算群的已读；压缩时随上下文一起压成摘要，位置不变。

### Claude 自带的 memory

不关（Claude 要原样运行，项目知识有用）。分工：Claude 的 memory 只记文件夹的项目知识；对话和各群发生的事由 Iridium 的身份记忆负责。给群里 agent 的说明加一句：不要把群里的对话写进自己的 memory。

### 压缩与已读

模型压缩上下文后，已读不变、不会重新读，需要时用 `message.list`（可按词搜）找回原话。

## 参考

## 遗留

- 拉起的会话有人直接说过话后是否进侧栏：先不管。
- 顶栏成员键是单独加载的，可能比对话晚一点出现；无 agent 的群页面没改；第二次回到看过的多 agent 会话仍会再取一次状态和成员。
- dsh 的模型里没有标“默认”（它没说哪个是默认）。
- `internal/session` 的 `TestQueue` 满负载下偶发失败，原因未查。
- 第一期开工前：确认测试实例的数据库版本，身份表的迁移编号不与别的会话撞车。
