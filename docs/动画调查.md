# 动画与布局：改动前调查

> 进度（2026-11-24）：§8 的第 1 步（移动记录）和第 3 步的跟随器已做，采用“滚动位置弹簧”；行离开改成当帧让位；现行规则见 `docs/动画.md`。没做：行表（第 2 步）、把折叠和换位并进一个控制器、侧边栏排序规则、长回合“留空位”的观感。§3.3 里 `stick.tsx` 和 `moves.ts` 的删除项已删，`chat.tsx` 里防跳的记录还在。

2026-11-24，`switch-perf` 分支。范围：对话区和侧边栏里一切会让内容换位置、变高矮、改滚动位置的东西。标“已量”的是逐帧数据，其余是读代码得出的。

## 0. 原则（kumo，2026-11-24）

1. **动画必须有，而且要精致。** 目标是不出错，不是靠不做动画来避免出错。
2. **动画只做一件事：让变化连续。** 最简单的过渡，不炫技；多一种动法就多一种出错的方式。
3. **不是什么东西都能让页面动。** 能动页面的原因逐条登记，没登记的不许带着页面动。
4. **方向确定。** 每个原因只准一个方向；一次移动不掉头。
5. **可量化。** 每条规则都有能自动跑的指标。

## 1. 现状

### 1.1 现在有五套东西在动页面

| 调度器 | 文件 | 管什么 | 靠什么协调 |
|---|---|---|---|
| 贴底滑动 | `chat/stick.tsx`（661 行） | 对话在底部时的跟随：`follow` 判断、`glide` 弹簧（加在看得见的行上）、`pin` 改滚动位置、地板占位（`floor`）、暂扣位移（`held`）、自己变高的东西登记（`moving`）、折叠点击（`toggleFold`）、往上翻页（`back`） | 8 个常数 |
| 行换位 | `moves.ts` `play`，入口 `motion.ts` `useMoves` | 标了 `data-flip` 的行顺序变了，从旧位置滑到新位置 | `occupy` / `freeIn` 和贴底滑动互相等 |
| 行离开 | `moves.ts` `useLeaving`、`Leaving`；`motion.css` `g-depart` | 走掉的行先淡出再收掉位置（高度动画） | 定时器 |
| CSS 手势 | `motion.css` | `g-reveal`（高度展开）、`g-arrive`（升入）、`g-fade`、`g-pop`、`g-unfold` 等 | 无，各自跑 |
| 整页切换 | `motion.ts` `pageTurn` | 会话之间切换，浏览器的 View Transition | `WAIT_FOR_PAGE`、`RAPID` |

另有两处不属于任何一套：发送气泡的 `pushIn` / `fadeIn`（`motion.ts`，手动对齐时间线），长文折叠自己的高度动画（`chat/longwords.tsx`）。

### 1.4 已量到的问题

- 一个 agent 回合（13 秒，没有中途发消息）：锚点消息有 11 帧往下走，最大约 58 px，随后往上约 136 px。这段时间总高度和滚动位置都没变，是位移动画把行画偏了。哪一套引起的还没查清。
- v0.2.62 的回归：27 帧往下，回合结束时下坠约 958 px。原因是同一句话既在工作块里又进了频道，撤掉一份时两套动画各自反应。`03637c2` 已修。
- 位移动画加在整列上，WebKit 多占 1.3 GB（11-23 已改成只加在看得见的行上）。

共同点：**同一批行同时受两三套动画作用，加上一个事后根据“高度变了”去猜原因的监听。**

## 2. 新版：谁还能动页面

### 2.1 只有四类事能改布局

| 类 | 包含（对应上表 #） | 方向 | 动法 |
|---|---|---|---|
| A 末尾长出来 | 1、2、10 | 只许向上 | 上面的内容平滑上移 |
| B 一行变高矮 | 6、7、8、9 | 展开向下撑、收起向上收；这一行以上不动 | 这一行高度过渡，下面的跟着走 |
| C 一行离开或换位 | 11、12 | 按新旧位置 | 从旧位置滑到新位置；离开的先淡出 |
| D 人的操作 | 3、4、5、17、18、19、20 | 跟手 | 3、4 同帧跟随；滚动类交给浏览器 |

### 2.2 新版不再触发移动的

| # | 现在 | 新版 |
|---|---|---|
| 13、14 | 活动行换内容、工作行按旧高度撑着 | 活动行固定高度；占位删掉 |
| 15 | 草稿变正式消息、步骤并进折叠 | 行表里是同一行，身份不变，不拆不建；高度若变，按 A 或留空位处理 |
| 16 | 晚到的内容事后撑开 | 图片按服务器给的宽高占位；卡片、“做了什么”按已知高度或一行占位；已读标记、表情、状态灯浮在行上不占位 |
| 回合中变矮 | 地板占位 350 ms 后收回，对话落下 | agent 引起的变矮不下落，空位留到回合结束或人操作时一次收回 |
| 同一句话搬家 | 先在工作块里、再成频道消息，撤一份建一份 | 同一行，只改所属 |
| 人翻上去时 | 靠规则判断该不该动 | 屏幕内位移恒为 0，只亮“新消息”键 |

## 3. 调度器：新增、修改、删除

### 3.1 新增

| 名字 | 职责 |
|---|---|
| 行表（`rowsOf`，纯函数） | 记录 + 频道消息 + 各 agent 状态 → 有稳定 key 的行表。现在散在 `chat.tsx` 主函数、`merge.ts`、`turns.ts`、`atwork.tsx`、`page.tsx` 的规则收到这里 |
| 登记表（一个文件） | 每个原因一行：名字、属于 A–D 哪类、方向、时长上限。代码和文档都以它为准 |
| 布局控制器 | 唯一能做位移和高度动画的地方。入口一个：组件在改布局前报原因。它在提交前后各量一次看得见的行，按登记表决定怎么过渡 |
| 跟随器 | A 类专用：让底部跟上。用“滚动位置弹簧”还是“行位移”，原型量过再定（§6） |
| 移动记录 | 每次移动记一条：原因、方向、距离、时长、是否登记。开发版可见，测试读它 |

### 3.2 修改

| 现有 | 怎么改 |
|---|---|
| `Stick` | 只留：是否在底部、分辨人的滚动、翻页、“新消息”键。跟随交给跟随器 |
| `moves.ts` `play` | 并进控制器，成为 C 类的实现 |
| `useLeaving` / `Leaving` | 保留“走掉的行多留一会儿”，只做淡出；收位置交给控制器 |
| `Arrive`、`g-arrive`、`g-fade` | 只保留透明度和升入（不改大小的部分） |
| `g-reveal` | 对话区内不再直接用；展开收起改成报给控制器。输入框、弹窗里的照旧 |
| `usePaced` | 侧边栏排序规则收紧后删除（见 §3.3） |
| `pageTurn` | 不动 |

### 3.3 删除（每项在对应场景指标全过后才删）

- `moves.ts`：`occupy`、`freeIn`、`paceWait`、`BEAT`、`ACTED`。
- `motion.ts`：`pushIn`、`fadeIn`、`pushing` 的时间线对齐。
- `chat.tsx`：`workH`、`justRested`、`rest`、`flew`、`bubbles` 这些防跳的记录；`drawnTurns` 的 `stamp`（行表有了身份后按行判断）。
- `longwords.tsx`：自己的 `glide`。
- `motion.css`：`g-depart-room`。

## 4. 以后的规范

1. 组件只画最终状态。对话区和侧边栏的代码里不出现：会改大小的 CSS 过渡、`animate()`、写滚动位置、`flushSync` 之后量高度。只有控制器和跟随器两个文件例外。用代码检查强制。
2. 要让页面动，先在登记表加一行，写明类别和方向，再加一个场景测试。
3. 晚到的数据必须先占位。新加一行、一张卡片时，回答“数据什么时候到、到之前占多高”。
4. 进场、出场只改透明度和不占位的位移，不改大小。
5. 一样东西在行表里只有一行。状态变了改这一行的属性，不撤掉重建。
6. 时间只用 `--move`、`--fade`、`--reveal` 三个量。新增时间常数要说明它在等什么；用来让两段动画互相让路的不许加。
7. 减少动画（系统设置）时：位置直接到位，只留淡入淡出。

## 5. 文档怎么写

- `docs/前端设计规范.md` 里“动画加在谁身上”“对话的移动”“动画协调”“后到的不撑开”四节现在是事故记录的累积（每条后面跟着日期和当时的现象）。合成一节“布局与动画”，只写现行规则：§0 的原则、§2.1 的四类、§4 的规范，共一页。
- 新建 `docs/动画.md`：登记表（从代码里那个文件抄，改代码时一起改）、验收场景和指标、“加一种会动的东西”的步骤。
- 为什么这样定、当时出过什么问题，写在提交说明和登记表那一行的注释里，不写进规范正文。
- 本文件是一次性的调查，方案落地后删掉。

## 6. 验收

| 指标 | 算法 | 要求 |
|---|---|---|
| 掉头次数 | 一次事件内位移方向改变的次数 | 0 |
| 逆向帧数 | 与登记方向相反的帧数 | 0 |
| 路程比 | 每帧位移绝对值之和 ÷ 净位移 | 1.0 |
| 落定时间 | 事件到位置不再变 | 不超过 `--move` 的规定倍数 |
| 未登记次数 | 没报原因的移动 | 0 |

场景：发消息；agent 回合（做步骤、中途说话、结束）；回合中途发消息；两个 agent 同时工作；图片晚到；输入框变高矮；折叠展开；往上翻到顶；翻上去时来新消息；切换会话；手机键盘；侧边栏重排。Chromium 和 WebKit 各跑一遍。测量脚本从 `/tmp/irperf` 搬进 `web/scripts`。

## 7. 没验证的和要定的

- 跟随器用哪种：滚动位置弹簧（方向天然确定、不产生图层，但每帧在主线程上）还是行位移（在合成线程上，但会画偏）。先做原型量。
- `column-reverse` 贴底在 WebKit 下、配合整页切换的表现。
- 控制器每次提交量位置的开销（只量看得见的行）。
- 长回合是否改成“问题送到上方、回答往预留的空位里长”。这会改变观感，等 kumo 定。
- agent 的话在工作块里和在频道里外观不同（有没有头像和名字行）。要身份不变，需要两种状态共用一个外框，是设计问题。
- §1.4 那 58 px 的来源。加上移动记录后第一件事就是查它。

## 8. 顺序

1. 移动记录：给 §1.3 每个入口标原因，不改行为，得到真实清单。
2. 行表和稳定身份，先补真实数据的回放测试。
3. 原型，定跟随器。
4. 侧边栏先迁到控制器（只有 C 类）。
5. 对话区按场景逐个迁，过一个删一块旧代码。
6. 加代码检查，改规范文档。
